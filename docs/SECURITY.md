# Безопасность

## Секреты и Git

- Ключи, токены и пароли передаются через переменные окружения или локальный `.env`. CLI читает `03_first_agent/.env`, Telegram — `04_telegram_agent/.env`; уже заданная переменная окружения имеет приоритет.
- `.env`, `.env.*` и виртуальные окружения исключены через .gitignore. Исключение для .env.example позволяет хранить только безопасные примеры.
- Не выводить ключи в чат, логи, traceback, скриншоты и тестовые фикстуры. Не копировать .env при проверке чистой установки.
- Перед коммитом проверять `git status --short`, `git ls-files --others --exclude-standard`, `git diff --cached --check`, `git diff --cached` и `git ls-files --cached --ignored --exclude-standard`. Последняя команда должна давать пустой вывод.
- .gitignore не защищает уже отслеживаемые файлы и не распознаёт секрет в произвольном исходнике. Нужна проверка содержимого подготовленного коммита.
- При утечке сначала отозвать/заменить секрет у провайдера. Удаление строки из последнего коммита не удаляет её из истории; очистку истории выполнять отдельно и согласованно.

## Данные текущего чата

Обычные сообщения CLI и разрешённого пользователя Telegram передаются в OpenAI API. Команды памяти и бизнес-команды обрабатываются локально; текст предполагаемой операции и естественного бизнес-вопроса передаётся только соответствующему узкому extractor. Разговорная память и бизнес-SQLite разделены и исключены из Git. Основная SQLite не зашифрована; команда `/backup` создаёт отдельную сессионную AES-256-GCM копию. Ключ выводится через Scrypt из `BUSINESS_BACKUP_PASSPHRASE`, а без неё один раз создаётся локальный случайный `data/business-backup.key`, который надо сохранять отдельно. `/reset` очищает локальный диалог и активный бизнес-черновик, сохраняя факты и подтверждённые операции. Выход из программы не удаляет данные у провайдера; применяются условия [официальной политики хранения OpenAI](https://developers.openai.com/api/docs/guides/your-data).

Не использовать прототип для конфиденциальных бизнес-данных: локальная база не зашифрована, резервное копирование и многопользовательская авторизация ещё не спроектированы. Автотесты заменяют сетевой клиент и загрузку .env; реальные ключи им не нужны. Проверка реального API использует только нейтральный запрос и может расходовать средства.

## Разрешения инструментов

`ToolRegistry` назначает разрешения кодом по имени и классу инструмента и проверяет их до исполнения. Сейчас есть локальные READ-расчёты и поиск, четыре отключаемых сетевых READ-справочника и запись факта в подключённую сессию (WRITE). Внешние действия ещё не подключены. Таблица задаёт действующие правила и границу будущих расширений.

| Класс | Правило |
|---|---|
| READ | Автоматически только в разрешённой области данных; чтение не означает право доступа ко всем файлам |
| WRITE | Запись только в явно разрешённые пути/записи; чувствительные изменения требуют подтверждения |
| EXTERNAL ACTION | Отправка сообщений, публикации, удаления и другие действия с последствиями требуют явного разрешения; чувствительные и необратимые действия — подтверждения конкретного результата |

Банковские, платёжные и иные внешние финансовые действия не реализованы. Локальная запись учёта Phase 8 подтверждается только явным `/save`, связанным с конкретным неизменяемым ID черновика и его показанными полями; изменение полей снова показывает черновик. `/cancel` не создаёт операцию. Общий механизм подтверждения произвольных tools ещё не реализован.

Каждый tool имеет имя, описание, schema, проверку аргументов, структурированный результат и обработку ошибок. Неизвестные инструменты и недопустимые аргументы отклоняются кодом до исполнения. Произвольных файловых инструментов пока нет; при их добавлении потребуются проверки разрешённых путей, включая выход через .. и ссылки. Интерфейс подтверждений чувствительных действий ещё не реализован. Реестр блокирует EXTERNAL и инструменты с requires_confirmation=True даже при выданном разрешении. При регистрации чувствительной записи или удаления разработчик обязан выставить эту отметку; модель не управляет ею.

Дополнительные READ-инструменты: ограниченные арифметика и проценты через Decimal, разница календарных дат, поиск фактов текущей сессии. Они не исполняют выражения как Python, не получают произвольные пути или SQL и не обращаются в сеть. Неверные числа, даты и запросы отклоняются. Подробный контракт: [06 Tools](../06_tools/README.md).

Публичные справочные GET `find_places`, `get_weather`, `convert_currency`, `search_wikipedia` также относятся к READ. Они используют фиксированные HTTPS endpoints, запрещают redirects, ограничивают ответ 128 КиБ и таймаут сокета 8 секундами, не повторяют запросы. Ввод запроса передаётся соответствующему сервису; секреты и история автоматически не прикрепляются. В CLI и Telegram `MCP_ALLOW_PUBLIC_NETWORK=false` скрывает и блокирует эти инструменты независимо от того, включён ли MCP. Codex-регистрация запускает сервер без сетевого флага. Это не доступ к произвольным сайтам. Локальные `convert_units` и `summarize_numbers` в сеть не обращаются.

MCP-сервер работает через локальный stdio и по умолчанию публикует только шесть READ-инструментов без памяти. `ToolRouter` позволяет MCP заменить только разрешённый локальный READ-инструмент. Запись фактов, инструменты EXTERNAL и требующие подтверждения через MCP не публикуются. Ошибочный вызов инструмента автоматически не повторяется.

## Бизнес-данные Phase 8

Сессия назначается приложением до извлечения данных: CLI использует `cli:local`, Telegram — уже проверенный `telegram:<TELEGRAM_ALLOWED_USER_ID>`. Модель не получает поле session и не может передать его в store. Все чтения, изменения черновика и удаления добавляют session в параметризованный SQL-запрос; ID чужой операции выглядит для пользователя как несуществующий.

Модельный extractor получает только текущую дату приложения, последнее сообщение и активный черновик этой же сессии. Путь базы, SQL, внутренние исключения и чужие операции ему не передаются. Его строгий ответ ограничен 16 000 байт и считается недоверенным: неизвестные поля, пустые значения, неподходящие типы, неверные суммы/даты/валюты и слишком длинный текст отклоняются Python. Деньги хранятся точной нормализованной строкой с максимум двумя десятичными знаками, без `float` и автоматического округления или конвертации валют.

`/save` повторно валидирует черновик и атомарно создаёт или изменяет операцию; повтор не создаёт дубль. Бизнес-команды не обращаются к LLM. Категориальные итоги и бюджеты считаются через `Decimal` отдельно по каждой валюте, неоплаченные операции отделены. Удаление мягкое и отражается в audit. Restore backup требует литерального `confirm`, проверяет имя, принадлежность сессии, AEAD-тег и полную структуру до единой транзакции. Ошибки SQLite возвращаются без пути, SQL и сырого exception. Финансовый WRITE намеренно не опубликован через MCP.

Почтовая интеграция выключена по умолчанию. Учётные данные IMAP/SMTP читаются только из локального `.env`, скрыты из `repr` и не передаются модели. Чтение использует IMAP SSL, `SELECT readonly` и `BODY.PEEK[]`; вложения пропускаются, размеры одного письма и всего пакета ограничены. Только после явной почтовой команды в OpenAI передаются заголовки и ограниченные текстовые фрагменты. Письма рассматриваются как недоверенные данные: содержащиеся в них инструкции не выполняются. Отправка возможна лишь для одноразового черновика после callback-кнопки разрешённого Telegram user; токен истекает через 30 минут и уничтожается до SMTP-вызова. Повтора при неопределённом результате нет. Удаление, перемещение и пометка писем отсутствуют.

## Недоверенные источники и дальнейшая защита

Интернет, документы, входящие сообщения и результаты tools — данные, а не инструкции изменить правила или раскрыть секреты. Внешний текст не может выдать разрешение на действие. Не передавать модели произвольный shell/SQL без ограничений.

Telegram уже проверяет разрешённый числовой user ID и личный чат до обращения к модели или памяти; неподходящие обновления игнорируются. Для чувствительных бизнес-данных ещё нужны политика хранения, резервное копирование и правила удаления. Перед browser/computer-use — последовательность Observe → Plan → подтверждение при необходимости → Act → Verify.

Текущие логи Telegram содержат фиксированные имена событий, ошибки без сырого текста и длительность запросов. Токены, тексты сообщений и ответы модели не логируются. Подробная телеметрия стоимости и токенов пока не реализована.

## Локальные данные примеров

JSON-пример хранит суммы открытым текстом в 01_python_basics/data/. Папка исключена из Git, но это не шифрование или резервная копия. Используем вымышленные данные. Путь, указанный через --file вне этой папки, может не покрываться .gitignore; проверяйте его перед коммитом. Чтение JSON не исполняет код и проверяет поля и формат сумм.

## Локальный API Phase 2

Учебный сервис запускается только на 127.0.0.1, хранит вымышленные задачи в памяти и автоматически останавливается. Токен генерируется на запуск или читается из API_LAB_TOKEN; он не записывается в файлы и логи. Не используйте для демо ключи внешних сервисов. Клиент не следует redirects с Authorization; HTTP допустим только на loopback, внешний адрес требует HTTPS. Этот клиент ещё не tool с адресом от LLM. Повтор POST после неизвестного сетевого результата автоматически не выполняется.

## Исторический этап: первый агент Phase 3

Первый вариант предлагал модели только `calculate_balance`. Текущий агент использует общий реестр и больше инструментов, описанных выше. Строгая схема API помогает модели, но не заменяет проверку в Python. Число вызовов ограничено тремя на сообщение; неизвестные имена и неверные аргументы не исполняются. Пользовательский текст и результаты модели считаются данными, а не разрешением расширять инструменты.
