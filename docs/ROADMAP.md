# Roadmap: AI Agents Lab → Personal JARVIS

## Цель

Создать персонального помощника для ежедневных задач: он понимает запросы, использует инструменты и API, хранит полезную информацию и выполняет разрешённые действия. Первый прикладной сценарий — учёт и анализ бизнес-данных через Telegram. Позже появятся веб, компьютер, 3ds Max и голос.

JARVIS — система из LLM, runtime, памяти, инструментов, базы данных, разрешений и интерфейсов. Принцип: **Build → Test → Understand → Improve → Integrate**. Каждый этап даёт работающий компонент; не создаём сложную инфраструктуру заранее.

**Текущее состояние на 2026-09-15:** локально готовы этапы 0–8. CLI и Telegram используют общий агент, SQLite-память, инструменты и подтверждаемый учёт доходов/расходов по категориям; MCP-сервер подключён к обоим интерфейсам и зарегистрирован в Codex. Справочные сетевые инструменты на этой рабочей машине выключены. После Phase 8 прошли 158 offline-тестов, `pip check` и `git diff --check`. История ниже сохраняет результаты проверок на момент каждого этапа; меньшие числа тестов в старых записях не описывают текущий прогон. Код ещё не закоммичен и не отправлен на GitHub.

## Phase 7: MCP

План сначала записан в 07_mcp/README.md, затем реализован локальный stdio-сервер на официальном Python SDK MCP 2.0.0. Он переиспользует ToolRegistry: по умолчанию видны шесть локальных READ-инструментов, четыре публичных GET включаются только флагом процесса. Память, запись и внешние действия через MCP не опубликованы. Сервер возвращает структурированный результат и текстовый JSON, проверяет аргументы и разрешения, ограничивает частоту и число одновременных вызовов. Все 123 offline-теста, включая настоящий stdio-обмен, `pip check` и `git diff --check` прошли 2026-09-15. Подключение конкретного внешнего MCP-хоста тогда не проверялось. Инструкция подключения — в 07_mcp/README.md. Следующий этап разработки — Phase 8: Business Agent.

Дополнение 2026-09-15: CLI и Telegram могут подключаться к этому серверу как MCP-клиенты через `MCP_ENABLED`, `MCP_ALLOW_PUBLIC_NETWORK` и `MCP_TOOL_NAMES`. ## Phase 8: Business Agent

Поверх прежнего `FirstAgent` добавлен общий `BusinessAgent`. Модель предлагает намерение и явно названные поля, включая назначение расхода или направление дохода в `category`; Python заново проверяет тип операции, точную сумму через Decimal, валюту, дату и длины текста. Неполный сессионный черновик можно последовательно дополнить; запись выполняется только через `/save`, `/cancel` её отменяет, `/draft` показывает состояние. `/records [N]`, `/categories` и сессионный `/delete ID` работают детерминированно без LLM.

Черновики и операции хранятся в отдельной `08_business_agent/data/business.sqlite3`, а не в разговорной памяти. ID, session и created_at задаёт доверенный код. Сохранение атомарно и идемпотентно по ID; SQLite-запросы параметризованы, разные CLI/Telegram-сессии изолированы. Общий runtime, tools и MCP не дублировались; бизнес-WRITE не опубликован через MCP.

Phase 9 добавляет проекты и статусы оплаты, детерминированные отчёты, read-only вопросы обычным языком, aliases категорий, бюджеты, подтверждаемые шаблоны, CSV, soft delete/restore, аудит, зашифрованные backup, read-only анализ почты через IMAP и одноразово подтверждаемые SMTP-ответы. Старая SQLite мигрируется на месте. Банковских действий, налоговой отчётности, автоматических проводок, удаления/перемещения писем и смешивания валют нет.
