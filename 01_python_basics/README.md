# 01 Python Basics

Короткие практические примеры для чтения кода будущего агента.

## Пример 1: выручка и расходы

[business_operation.py](business_operation.py) спрашивает две суммы и вычисляет разницу. Например, выручка 120000 и расходы 90000 дают 30000.00.

Суммы должны относиться к одному периоду и одной валюте. Это разница двух введённых сумм, а не полный бухгалтерский расчёт прибыли. Данные пока не сохраняются.

### Запуск

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe 01_python_basics/business_operation.py
```

Также можно использовать `py -3.11 01_python_basics/business_operation.py`. Пример использует только стандартную библиотеку Python: интернет, ключи и установка новых зависимостей не нужны.

```text
Выручка: 120000
Расходы: 90000
Выручка: 120000.00
Расходы: 90000.00
Разница: 30000.00
Выручка превышает расходы.
```

Допустимы `1250,50`, `1250.50` и `0`. Вводите без разделителей тысяч: до 12 цифр целой части, до двух знаков после запятой. Отрицательные суммы, лишние знаки после запятой и текст вызывают подсказку и повторный ввод. Отрицательный результат допустим: расходы могут превышать выручку. Ctrl+C или конец ввода отменяют расчёт.

### Как устроено

- Переменные `revenue`, `expenses`, `balance` хранят выручку, расходы и разницу.
- `parse_amount()` проверяет текст и создаёт `Decimal`: десятичные суммы остаются точными, без float и скрытого округления.
- `calculate_balance()` выполняет вычитание отдельно от ввода и вывода.
- `read_amount()` повторяет запрос при неверном вводе.
- `main()` связывает шаги и выводит результат с двумя знаками после точки.

### Проверка

Только этот пример, без зависимостей чата:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_business_operation.py -v
```

Все тесты проекта, включая существующий чат:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Пример 2: сохранить и прочитать JSON

[business_json.py](business_json.py) сохраняет одну операцию в файл и читает её при следующем запуске. Это практика работы с постоянными данными, а не готовая база Business Agent.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe 01_python_basics/business_json.py save
```

Введите, например, выручку 120000 и расходы 90000. Программа создаст `01_python_basics/data/operation.json`, прочитает его обратно и покажет разницу. После завершения программы прочитайте запись отдельной командой:

```powershell
.\.venv\Scripts\python.exe 01_python_basics/business_json.py read
```

Файл выглядит так:

```json
{
  "revenue": "120000.00",
  "expenses": "90000.00"
}
```

Суммы хранятся строками и при чтении превращаются в Decimal. Разницу вычисляет код первого примера; отдельно в файле она не дублируется.

Один файл содержит одну операцию. Повторный save не перезаписывает существующий файл. Для другой записи задайте другой путь (относительный путь считается от текущей папки терминала):

```powershell
.\.venv\Scripts\python.exe 01_python_basics/business_json.py save --file 01_python_basics/data/second.json
.\.venv\Scripts\python.exe 01_python_basics/business_json.py read --file 01_python_basics/data/second.json
```

По умолчанию путь всегда привязан к папке программы, независимо от места запуска. Папка data исключена из Git. Это обычный незашифрованный локальный файл; для примеров используйте вымышленные суммы. Если выбрали другой путь вне data, правило исключения на него не распространяется.

### Что здесь полезно понять

1. Python-словарь описывает структуру записи: имя поля → значение.
2. json.dumps превращает данные в текст, json.load читает их обратно.
3. Функции первого примера можно импортировать и использовать повторно.
4. Прочитанный файл тоже нужно проверять: он может отсутствовать, быть повреждён или содержать неправильные суммы.

При ошибке программа выводит пояснение и возвращает код 1. Повреждённый файл не исправляется автоматически. Это небольшой пример для последовательного локального запуска; транзакции, журнал операций, резервное копирование и совместный доступ пока не реализованы.

### Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_business_json.py -v
```

Новых зависимостей, API и ключей не требуется.

## Пример 3: калькулятор как инструмент

Здесь расчёт получает интерфейс для вызова из другой программы. Модель пока не подключена: демонстрационная программа сама вызывает инструмент.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe 01_python_basics/tool_example.py 120000 90000
```

Два числа в команде — выручка и расходы за один период в одной валюте. Результат:

```json
{
  "tool": "calculate_balance",
  "ok": true,
  "value": "30000.00",
  "error": null
}
```

- `tool` — имя вызванного инструмента.
- `ok` — успешно ли выполнен расчёт.
- `value` — точная сумма в виде строки; при ошибке null.
- `error` — описание ошибки; при успехе null.

Попробуйте ошибочный ввод:

```powershell
.\.venv\Scripts\python.exe 01_python_basics/tool_example.py ошибка 90000
```

Получите `ok: false` и пояснение вместо аварийного завершения с traceback. Код выхода при ошибке — 1; при успехе — 0. Неверная форма самой команды обрабатывается argparse и даёт подсказку с кодом 2.

### Что показывают классы и модули

[calculator_tool.py](calculator_tool.py) — модуль с двумя небольшими классами. `CalculatorTool` объединяет имя, описание и метод run. `ToolResult` — dataclass: описание полей одного результата; Python сам создаёт для него конструктор.

[tool_example.py](tool_example.py) импортирует инструмент, создаёт его экземпляр и вызывает run. Преобразование результата в JSON и вывод находятся здесь. Сам инструмент не спрашивает ввод, не печатает и не сохраняет файлы — поэтому позже его сможет вызвать иной интерфейс.

Проверка сумм и вычитание импортированы из первого примера. Не нужно заново писать арифметику. Это пока локальный учебный контракт, а не универсальная система tools из Phase 6: registry, JSON Schema и permission layer ещё не создаём.

### Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_calculator_tool.py -v
```

Новых зависимостей нет.

## Пример 4: данные из веб-сервиса и async/await

[http_example.py](http_example.py) выполняет два HTTP GET к учебному сервису JSONPlaceholder: получает задачи /todos/1 и /todos/2. Это вымышленные данные, не ваши реальные задачи.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe 01_python_basics/http_example.py
```

Программа выводит номер, название и состояние каждой задачи. Нужен интернет, но ключ API и новые зависимости не требуются. Файлы не записываются. Доступность внешнего сервиса может меняться.

### Настройка через environment variable

Адрес по умолчанию — https://jsonplaceholder.typicode.com. Переменная окружения — настройка процесса, которую программа читает через os.getenv. Это позволяет менять адрес, не редактируя Python:

```powershell
$env:HTTP_EXAMPLE_BASE_URL = "https://jsonplaceholder.typicode.com"
.\.venv\Scripts\python.exe 01_python_basics/http_example.py
Remove-Item Env:HTTP_EXAMPLE_BASE_URL
```

Последняя команда удаляет настройку текущего терминала и возвращает значение по умолчанию. Пример читает окружение процесса; .env автоматически не загружает. Безопасный пример настройки указан в корневом .env.example. Альтернативный сервис должен поддерживать /todos/1 и /todos/2 с полями id, title и completed. Адрес не должен содержать логин, пароль, query или fragment.

### Как работает ожидание

- fetch_todo — обычная функция: отправляет GET, читает JSON и проверяет структуру.
- async def объявляет функцию, которая может приостанавливаться в ожидании.
- asyncio.to_thread запускает блокирующий urllib в рабочем потоке, чтобы он не останавливал цикл asyncio.
- asyncio.gather запускает оба ожидания вместе; await ждёт результаты.
- asyncio.run запускает асинхронную главную функцию.

Поэтому программа может ждать ответ первого сервиса, пока идёт второй запрос. Это не делает сам сервер быстрее и не означает запуск фонового процесса после закрытия программы.

### Ошибки и границы примера

HTTP-ошибка, недоступная сеть, таймаут, повреждённый JSON и неправильные поля дают понятное сообщение. Успешный ответ одного запроса показывается даже при ошибке другого. Код выхода — 0 при двух успешных запросах, иначе 1.

Ограничение ответа — 64 КиБ; таймаут сетевых операций — 10 секунд. Это таймаут блокирующих сетевых операций, а не строгий предел полной длительности программы. При Ctrl+C уже работающий поток не обрывается мгновенно. Повторные попытки, авторизацию, POST и обработку rate limits отдельно реализуем в Phase 2.

### Проверка без интернета

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_http_example.py -v
```

Тесты подменяют HTTP; проверяют ответы, ошибки, настройку адреса и одновременную работу двух потоков.

Официальные источники: [urllib.request](https://docs.python.org/3.11/library/urllib.request.html), [asyncio и потоки](https://docs.python.org/3.11/library/asyncio-task.html#running-in-threads), [JSONPlaceholder](https://jsonplaceholder.typicode.com/guide/). Проверены 2026-09-14.
