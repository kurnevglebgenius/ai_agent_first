# 02 Web/API — Phase 2

Рабочий пример общения двух программ по HTTP: клиент создаёт учебную задачу на сервисе и читает её обратно. Он показывает GET, POST, JSON, авторизацию, timeout, retries и rate limits.

## Запуск одной командой

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe 02_web_api/demo.py
```

Либо `py -3.11 02_web_api/demo.py`. Новых зависимостей, интернета и внешнего аккаунта не требуется. Программа сама запускает временный сервис на 127.0.0.1 со свободным портом и останавливает его после демонстрации.

Ожидаемый результат:

```text
GET /tasks: записей 0
POST /tasks: HTTP 201, создана задача 1
GET /tasks: запись подтверждена — Проверить отчёт салона
GET /demo/rate-limit: HTTP 200, попыток 2
GET /demo/unavailable: HTTP 200, попыток 2
Неверный токен: HTTP 401, попыток 1
Медленный ответ: таймаут, остановка после 3 попыток.
Пример завершён. Локальный сервис остановлен; учебные записи удалены из памяти.
```

Сценарии 429, 503 и задержки намеренно воспроизводятся учебным сервисом. Это настоящие HTTP-запросы через локальный сокет, а не печать заранее заготовленных ответов. Настоящую систему ограничения частоты сервис пока не реализует.

## Что происходит

```text
demo.py → ApiClient → HTTP → локальный сервис → JSON → ApiClient → результат
```

1. GET /tasks получает список задач.
2. POST /tasks отправляет JSON с названием новой задачи.
3. GET /tasks проверяет, что задача действительно создана.
4. Демо показывает восстановление после временных ошибок и остановку при неверном доступе/таймауте.

Сервис хранит задачи только в оперативной памяти. При завершении они исчезают; это пример API, не база данных и не Business Agent.

## Авторизация и настройки

Клиент отправляет заголовок Authorization: Bearer <token>. Сервер проверяет токен до чтения или создания задач. Без правильного токена возвращает 401.

По умолчанию demo.py генерирует случайный временный токен в памяти и передаёт его клиенту и сервису. Токен не печатается и не записывается на диск. Если нужна своя настройка, используется переменная окружения API_LAB_TOKEN. Пример безопасного локального значения:

```powershell
$env:API_LAB_TOKEN = "local-demo-placeholder"
.\.venv\Scripts\python.exe 02_web_api/demo.py
Remove-Item Env:API_LAB_TOKEN
```

Файл .env автоматически не загружается. Для этого демо не нужны настоящие ключи OpenAI, Telegram или других сервисов. Значение placeholder подходит только для изолированного учебного запуска.

## Повторы и ошибки

| Ситуация | Поведение клиента |
|---|---|
| GET успешно | Возвращает HTTP-статус, JSON-объект и число попыток |
| GET: сеть/таймаут или 429, 502, 503, 504 | До 3 попыток всего |
| POST: любая ошибка | Только одна попытка, без автоматического повторения |
| 400, 401, 403, 404 и прочие постоянные ошибки | Без повторов |
| 3xx | Перенаправление не выполняется, чтобы не пересылать токен |
| Некорректный JSON, не объект или ответ больше 64 КиБ | Понятная ошибка без повторов |

Без Retry-After паузы перед повтором — 0.1 и 0.2 секунды. Retry-After поддерживается как число секунд и как HTTP-date. Если сервер просит ждать более 5 секунд, клиент прекращает автоматические повторы и сообщает о необходимости повторить позднее; он не делает запрос раньше срока. Некорректный заголовок заменяется стандартной паузой.

Таймаут — 2 секунды на блокирующие сетевые операции; для демонстрации медленного ответа — 0.03 секунды. Это не строгий предел всей операции: есть несколько запросов, сетевых ожиданий и паузы.

POST не повторяется, поскольку сервер мог сохранить запись до потери ответа. При сетевом сбое результат записи считается неизвестным. Идемпотентность и защиту от дубликатов для реальных сервисов проектируем по их контракту позже.

Ошибки клиента имеют поля status и attempts, но не включают сырой ответ сервера, токен или внутренние сетевые подробности. Код завершения демо — 0 при прохождении сценариев, иначе 1.

## Границы текущей реализации

Сервис слушает только loopback, не обслуживает файлы компьютера и не предназначен для публикации в интернете. Стандартный [http.server](https://docs.python.org/3.11/library/http.server.html) используется для локального примера, не production-развёртывания.

Клиент допускает HTTPS-адрес или HTTP на loopback. Redirects отключены. Это небольшой клиент для доверенного адреса, задаваемого разработчиком; доступ к произвольному URL от модели пока не предоставлен. Сервер проверяет название задачи и ограничивает тело POST 8 КиБ. Базы, общий tool framework, MCP и Telegram пока не добавлены.

## Проверки

Только Phase 2:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_web_api.py -v
```

Все проверки проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты не вызывают интернет: часть подменяет транспорт и ожидание, часть использует настоящий временный локальный HTTP-сервис.

Официальные источники, проверенные 2026-09-14: [urllib.request](https://docs.python.org/3.11/library/urllib.request.html), [HTTP и Retry-After — RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html), [429 Too Many Requests — RFC 6585](https://www.rfc-editor.org/rfc/rfc6585.html).
