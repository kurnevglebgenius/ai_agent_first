# 04 Telegram Agent

Telegram использует тот же `BusinessAgent` поверх `FirstAgent`, что и терминальный интерфейс. Бизнес-операции привязаны к разрешённому user ID; выбранные READ-инструменты могут идти через локальный MCP-сервер. Подробности бизнес-сценария: [08 Business Agent](../08_business_agent/README.md).

Бот — интерфейс к общему агенту; отдельного цикла вызова модели в нём нет.

```text
Telegram → telegram_api.py (long polling)
         → TelegramAdapter (доступ, команды, текст)
         → shared/agent_runtime/BusinessAgent.reply
         → draft/BusinessStore либо FirstAgent → OpenAIProvider/tools
         → ответ модели → TelegramAdapter → Telegram

03_first_agent/main.py → тот же shared/agent_runtime/FirstAgent
```

## Локальный запуск в PowerShell

Из корня проекта, Python 3.11 и существующее окружение `.venv`:

```powershell
if (-not (Test-Path .venv)) { py -3.11 -m venv .venv }
.\.venv\Scripts\python.exe -m pip install -r 04_telegram_agent/requirements.txt
if (-not (Test-Path 04_telegram_agent/.env)) {
    Copy-Item 04_telegram_agent/.env.example 04_telegram_agent/.env
}
```

Создайте бота через [BotFather](https://t.me/BotFather), командой `/newbot`. В локальном `04_telegram_agent/.env` заполните:

- `TELEGRAM_BOT_TOKEN` — токен созданного бота;
- `TELEGRAM_ALLOWED_USER_ID` — ваш числовой Telegram user ID, не username и не ID бота;
- `OPENAI_API_KEY` — ваш ключ для существующего агента.

Свой ID можно найти в экспорте данных Telegram Desktop в JSON: поле `personal_information.user_id`. Нужен только экспорт информации профиля. Не передавайте токен сторонним ботам и не вставляйте его в URL браузера.

Загружается только `04_telegram_agent/.env`; файл раздела 03 и корневой `.env` не читаются. Уже заданные environment variables имеют приоритет. Конфигурация получает значения через `os.environ`, токен не хранится в коде. `.gitignore` уже исключает `.env`. Не присылайте ключи в чат и не коммитьте их.

```powershell
.\.venv\Scripts\python.exe 04_telegram_agent/main.py
```

Откройте личный чат с ботом. Для остановки нажмите Ctrl+C. Достаточно одного процесса; компьютер должен оставаться включённым. Входящий порт и публичный сервер не нужны. Используйте корневое `.venv`: старое окружение `03_first_agent/.venv` не содержит MCP, пока в него не установлены текущие зависимости.

## Понятные команды и меню

При запуске бот сам обновляет меню команд Telegram через `setMyCommands`. Сбой обновления меню не останавливает polling: все команды по-прежнему можно написать вручную. Основные короткие названия:

| Команда | Что делает |
| --- | --- |
| `/list [N]` | Показывает последние 1–20 доходов и расходов |
| `/summary [период]` | Строит финансовую сводку |
| `/money` | Группирует суммы по категориям и валютам |
| `/mail` | Проверяет подключение деловой почты |
| `/mail_report [дни]` | Анализирует письма за 1–30 дней |
| `/mail_reply [дни]` | Предлагает ответ с кнопками подтверждения |
| `/trash`, `/restore_record ID` | Показывает и восстанавливает удалённые операции |
| `/backup_list`, `/backup_restore ФАЙЛ confirm` | Показывает и восстанавливает резервные копии |

`/help` показывает краткую справку, а `/help учет`, `/help отчеты`, `/help почта`, `/help данные` и `/help память` — подробности по одному разделу. Старые названия (`/records`, `/report`, `/categories`, `/email-status` и другие) оставлены рабочими для обратной совместимости. Названия в меню состоят только из латинских букв и `_`, как требует Telegram.

Если включаете MCP, добавьте в локальный `.env` `MCP_ENABLED=true`. Параметр `MCP_ALLOW_PUBLIC_NETWORK=false` оставляет четыре справочных сетевых инструмента выключенными; `MCP_TOOL_NAMES=` выбирает все доступные инструменты сервера. Значения этих параметров не заменяют ключи Telegram и OpenAI. После изменения `.env` перезапустите бот. Для проверки MCP без отправки сообщения в Telegram используйте `.\.venv\Scripts\python.exe 07_mcp/client.py check`.

## Ручные проверки

1. `/start` — бот показывает начало работы и команды.
2. `/help` — выводит помощь без обращения к LLM.
3. `Вчера потратил 450 на рекламу` → `BYN` — агент должен дополнить один черновик и показать нормализованную дату.
4. `/save`, затем `/list` — должна появиться ровно одна операция; повторный `/save` не создаёт дубль.
5. `/draft`, `/money`, `/summary`, `/budgets`, `/templates`, `/edit` и команды корзины работают с локальными данными текущего разрешённого пользователя. `/mail` и `/mail_report [дни]` дают read-only сводку, `/mail_reply [дни]` показывает ответ с кнопками подтверждения; настройка и полный список — в `/help` и [README бизнес-агента](../08_business_agent/README.md).
6. `/status` — сообщает о работе бота и наличии контекста. Команда не проверяет доступность OpenAI.
7. `/reset` — сбрасывает диалог и незавершённый черновик, сохраняя факты и операции.

Отдельно проверьте отказ в доступе с другого аккаунта: бот должен молчать и не вызывать модель. В группах он тоже не отвечает. Фото, голос и документ от разрешённого пользователя получают подсказку отправить текст; файлы не скачиваются, подписи не передаются агенту.

## Файлы и ограничения

- `main.py` — загрузка `.env`, сборка runtime и адаптера, безопасное завершение.
- `config.py` — обязательный токен, числовой user ID и ключ LLM; при неверной настройке запуск прекращается.
- `command_catalog.py` — единый текст `/start`, тематическая справка и безопасный список команд меню Telegram.
- `telegram_api.py` — только HTTP, getUpdates, sendMessage, sendChatAction и setMyCommands, таймауты, разбиение длинных ответов, ограниченные повторы при 429.
- `telegram_adapter.py` — проверка отправителя до любых действий, справка, меню, команды и передача текста в `agent.reply`. Ветка неподдерживаемого сообщения — место для будущих voice/photo/document адаптеров.
- `../shared/agent_runtime/` — единственная реализация существующего агента; раздел 03 сохраняет совместимые импорты и терминальный запуск.

Сообщения обрабатываются последовательно. Во время ответа LLM команды ждут своей очереди; таймаут одного запроса LLM — 60 секунд, сетевого Telegram-запроса — 40 секунд. Это сетевые таймауты, не общий дедлайн agent loop. Автоматических повторов LLM нет.

Логируются только фиксированные события: запуск, отказ доступа, команда, запрос/ответ агента, ошибка, доставка, остановка. Токены, URL, тексты сообщений, ответы и traceback в лог не выводятся. Ошибка агента получает безопасный ответ; временная ошибка polling повторяется с паузой. Коды 401/404 означают проблему токена, 409 — конфликт polling/webhook. Остановите второй экземпляр или удалите ранее настроенный webhook самостоятельно; бот не меняет webhook автоматически.

При неудаче sendMessage обработанный запрос не запускается заново: ответ может быть потерян или доставлен частично. Уникальный ID защищает подтверждённую бизнес-запись от дубля при повторном `/save`. Offset живёт только в оперативной памяти; при аварийном перезапуске возможна повторная обработка последнего обновления. `/reset` удаляет локальный диалог и черновик, но сохраняет факты, операции, историю Telegram и данные у LLM-провайдера.

SQLite-память и MCP-клиент находятся в общем runtime. Прямой зависимостью `03_first_agent/requirements.txt` добавлен `mcp==2.0.0`; Docker и облачное развёртывание не нужны. HTTP-контракт, offset, ограничения сообщений и retry_after сверены с [Telegram Bot API](https://core.telegram.org/bots/api).

## Скорость ответа

На текущей сети проверка выявила недоступный IPv6: TCP к Telegram и OpenAI зависал, а IPv4 подключался за 0,05 секунды. Транспорт Telegram и клиент OpenAI в Telegram-точке входа теперь используют IPv4, сохраняя проверку HTTPS-сертификатов. Системные настройки и CLI не меняются. Для OpenAI используется HTTPTransport из httpx2, уже установленного зависимостью закреплённого OpenAI SDK. Новых пакетов не требуется. На сети только с IPv6 этот вариант потребует пересмотра.

Telegram использует gpt-5-mini с `OPENAI_REASONING_EFFORT=low` по умолчанию, даже если этой строки ещё нет в вашем .env. Меньший объём рассуждений может ускорить ответ, но снизить качество сложных задач. Можно задать `medium` или `high`; для эксперимента с минимальным временем — `minimal`. После изменения настройки перезапустите процесс. Настройки CLI остаются прежними. Параметр описан в [OpenAI Docs](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.2).

Обычные ответы Telegram теперь по умолчанию краткие. Это уменьшает число генерируемых слов и может сократить время ожидания; просьба «объясни подробно» сохраняет полный ответ. Числа, условия, единицы и источники агенту велено оставлять в ответе. CLI продолжает отвечать в прежнем стиле. Это подсказка модели, а не жёсткий предел длины. Согласно [руководству OpenAI по задержке](https://developers.openai.com/api/docs/guides/latency-optimization), сокращение вывода обычно влияет на время сильнее, чем сокращение входной инструкции. Оценивать скорость стоит на нескольких вопросах одинаковой сложности по логам времени LLM и ответа агента при запуске бота в терминале.

Перед обращением к модели бот показывает действие «печатает…». Локальный маршрутизатор без отдельного AI-вызова различает обычный разговор, запись операции и read-only вопрос к бизнес-данным. Поэтому обычный чат больше не проходит последовательно через два лишних бизнес-extractor, а операции и отчёты сохраняют специализированную проверку. Уровень `OPENAI_REASONING_EFFORT` от этого не меняется.

Логи `llm_request_finished duration_s=...` показывают время каждого запроса LLM, `agent_response duration_s=...` — всего ответа агента, `delivery_finished duration_s=...` — отправки в Telegram (включая неудачную попытку). Время включает сеть и работу удалённого API, их по этим замерам разделить нельзя. Запрос с калькулятором обычно требует двух обращений к LLM. Сообщения идут по очереди, поэтому новая команда может ждать предыдущий ответ. Настройка polling timeout=25 означает ожидание новых сообщений, а не обязательную паузу перед каждым ответом.

## Проверки без внешних API

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют runtime с настоящим калькулятором и подменённой моделью, бизнес-черновики, категории и операции, быстрый маршрутизатор, MCP-подключение, доступ, новые и старые команды, меню, тематическую справку, reset, сетевые ошибки, безопасные логи, длинные ответы и offset. Актуальное число тестов указывается результатом команды выше, а не поддерживается вручную в README.

## Память (Phase 5)

После перезапуска бот восстанавливает последние 10 обменов. Команды `/remember название = значение`, `/memory`, `/forget название` управляют фактами. `/reset` удаляет локальный диалог, сохраняя факты. Подробнее: [05 Memory](../05_memory/README.md).


Важные факты можно сообщать обычным текстом, например «меня зовут Глеб»: модель может сохранить их через remember_fact. Проверьте результат командой /memory. Автоматическое сохранение применяется к новым сообщениям после перезапуска.
