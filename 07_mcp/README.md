# Phase 7 — локальный MCP-сервер

## План реализации

1. Взять официальный Python SDK MCP 2.x и транспорт stdio. SDK обеспечивает протокол и совместимость клиентов; собственный JSON-RPC и HTTP-сервер здесь не нужны. Закрепить версию в требованиях раздела.
2. Сделать тонкий адаптер к `shared/agent_runtime/tools.py`: `tools/list` строить из разрешённых схем `ToolRegistry`, `tools/call` направлять в тот же реестр. Не копировать расчёты и предметную валидацию.
3. По умолчанию публиковать шесть локальных READ-инструментов: `calculate_balance`, `calculate_arithmetic`, `calculate_percentage`, `days_between`, `convert_units`, `summarize_numbers`. Четыре публичных справочных GET-инструмента включать только явным флагом `--allow-public-network`. Память, WRITE, EXTERNAL и действия с подтверждением не публиковать.
4. Возвращать результат MCP как текстовый JSON и `structuredContent` с теми же полями `ok`, `value`, `error`; ошибки аргументов и обработчиков отмечать `isError`. Неизвестное имя отклонять как ошибку протокола. Не выводить обычные сообщения в stdout, который занят протоколом. Ограничить поток вызовов к серверу.
5. Проверить список и схемы инструментов, разрешения, успешный вызов, неверные аргументы, ошибку предметной валидации и настоящий обмен с сервером через stdio. Выполнить все существующие offline-тесты и `git diff --check`.
6. Дописать инструкцию установки, настройки MCP-клиента, ручной проверки и границы безопасности; обновить общий roadmap после работающего результата.

## Границы этапа

Сервер запускается локальным клиентом как дочерний процесс. Он не использует OpenAI API, Telegram-токен и SQLite. У него нет доступа к диалогу или сессии пользователя, поэтому инструменты памяти здесь пока неуместны. Публичные GET передают внешним сервисам только аргументы конкретного вызова; право на сетевой режим задаёт владелец процесса, а не модель. MCP-клиент самостоятельно решает, когда вызвать опубликованный инструмент; сервер в любом случае повторно проверяет аргументы и разрешения.

План опирается на [официальную спецификацию MCP](https://modelcontextprotocol.io/specification/2026-07-28) и [документацию Python SDK 2.x](https://py.sdk.modelcontextprotocol.io/v2/advanced/low-level-server/), проверенные 2026-09-15. Низкоуровневый `Server` выбран потому, что он принимает существующие JSON Schema без генерации схем из новых Python-обёрток.

## Статус

Реализация находится в [server.py](server.py); зависимости раздела — в [requirements.txt](requirements.txt). План выше был записан до реализации. На 2026-09-15 все 137 offline-тестов проекта прошли, включая запуск сервера как дочернего процесса и вызов MCP-инструмента из цикла агента. `pip check` и `git diff --check` прошли. Живые запросы к модели внутри CLI/Telegram и сетевые инструменты через MCP отдельно не проверялись; вызов инструмента из нового сеанса Codex CLI подтверждён ниже.

## Установка и подключение

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r 07_mcp/requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Для проверки без настройки стороннего приложения есть собственный [клиент](client.py). Он запускает сервер как дочерний процесс, подключается по stdio и показывает результат:

```powershell
.\.venv\Scripts\python.exe 07_mcp/client.py check
.\.venv\Scripts\python.exe 07_mcp/client.py list --details
.\.venv\Scripts\python.exe 07_mcp/client.py call calculate_arithmetic --arg operation=add --arg left=0.1 --arg right=0.2
```

`check` проверяет согласование протокола, наличие безопасных инструментов и три локальных вызова. `list --details` показывает названия, описания и обязательные входные поля. `call` принимает повторяемые аргументы `--arg имя=значение`, печатает структурированный JSON и завершает работу с кодом 1 при ошибке инструмента. Ожидание подключения ограничено 15 секундами, списка или отдельного вызова — 20 секундами. Для просмотра сетевых инструментов добавьте `--allow-public-network` **перед** подкомандой, например `client.py --allow-public-network list`; это разрешает публичные GET только в запущенном клиентом сервере. Команда `check` сеть не вызывает.

## Наш агент как MCP-клиент

CLI и Telegram теперь могут выполнять выбранные инструменты через MCP. Установите зависимости из `07_mcp/requirements.txt` и внесите настройки в локальный `03_first_agent/.env` или `04_telegram_agent/.env` соответствующего интерфейса:

```dotenv
MCP_ENABLED=true
MCP_ALLOW_PUBLIC_NETWORK=false
MCP_TOOL_NAMES=calculate_arithmetic,days_between
```

`MCP_ENABLED=false` оставляет прямой вызов инструментов без MCP. При `true` агент один раз подключается к локальному серверу и держит соединение, пока работает CLI или Telegram. `MCP_TOOL_NAMES` перечисляет инструменты, которые нужно вызывать через MCP; если строка пустая, берутся все доступные инструменты сервера. Одноимённые локальные схемы заменяются, а остальные инструменты продолжают работать локально. `MCP_ALLOW_PUBLIC_NETWORK=true` включает четыре справочных сетевых инструмента; `false` скрывает и блокирует их в CLI и Telegram даже при выключенном MCP. Для Codex этот параметр из `.env` не действует: там сетевой режим задаётся флагом сервера в собственной конфигурации. Значения `MCP_*` не передаются модели как аргументы.

Проверить путь без вызова OpenAI можно командой `client.py check`, а полный цикл агента покрыт тестом с поддельным ответом модели. Для живой проверки задайте ваш `OPENAI_API_KEY`, запустите привычный CLI или Telegram и попросите выполнить расчёт из `MCP_TOOL_NAMES`. Живой запрос к модели расходует API-квоту. Если сервер недоступен при старте, интерфейс покажет ошибку настройки. Если связь пропадёт во время вызова, агент получит структурированную ошибку; текущий вызов автоматически не повторяется. Следующий запрос попытается восстановить соединение.

## Подключение в Codex

На этом компьютере сервер `ai-agents-lab` добавлен в глобальную конфигурацию Codex и виден в `codex mcp list` как `enabled`. Для нового компьютера используйте [официальную команду Codex](https://developers.openai.com/codex/mcp/):

```powershell
codex mcp add ai-agents-lab -- "C:/path/to/ai_agent_first/.venv/Scripts/python.exe" "C:/path/to/ai_agent_first/07_mcp/server.py"
codex mcp list
```

Замените путь на фактический абсолютный путь к проекту. Это подключение запускает сервер без публичной сети и не зависит от `MCP_ENABLED` в `.env` нашего Python-агента. На этом компьютере новый сеанс Codex CLI обнаружил `calculate_arithmetic` и реально вызвал его для 2 + 3, получив 5. Вызов из графического интерфейса Codex отдельно не проверялся. В неинтерактивном `codex exec` MCP-вызов требует разрешения: проверка прошла с `--approve-for-me`; запуск с политикой `approval: never` вызов отклонил.

В конфигурации локального MCP-клиента задайте команду для запуска сервера. Пути сделайте абсолютными: клиент может стартовать из другой рабочей папки. Например, если клиент использует формат `mcpServers`:

```json
{
  "mcpServers": {
    "ai-agents-lab": {
      "command": "C:/path/to/ai_agent_first/.venv/Scripts/python.exe",
      "args": ["C:/path/to/ai_agent_first/07_mcp/server.py"]
    }
  }
}
```

Замените `C:/path/to/ai_agent_first` на фактический путь к проекту. Для включения четырёх публичных справочных GET добавьте в `args` строку `"--allow-public-network"` и перезапустите сервер в клиенте. Процесс работает через stdin/stdout; запуск команды вручную без MCP-клиента ожидает сообщения и ничего не печатает. Ключ OpenAI и Telegram для MCP не требуются.

После подключения клиент должен увидеть шесть локальных инструментов. Для ручной проверки вызовите `calculate_arithmetic` с аргументами `{"operation":"add","left":"0.1","right":"0.2"}`: `value` должен быть `"0.3"`. Затем вызовите `days_between` для `2024-02-28` и `2024-03-01`: ожидается `{"days":2}`. Некорректный аргумент возвращает `isError=true`; вызов `remember_fact` или неизвестного имени отвергается протоколом.

## Контракт и ограничения

Сервер публикует `tools/list` и `tools/call`, включая исходные JSON Schema входа и общую схему ответа. Текстовый блок содержит JSON для клиентов, читающих только `content`; `structuredContent` содержит тот же объект. Поля: `ok` (успех), `value` (результат или null), `error` (сообщение или null). Повторной попытки после ошибки нет. Вход проверяется существующим `ToolRegistry` даже при прямом MCP-вызове.

По умолчанию сервер не делает сетевых запросов. Флаг включает только `find_places`, `get_weather`, `convert_currency`, `search_wikipedia` с фиксированными HTTPS endpoint, ограниченным ответом, таймаутом и без redirects; подробности — в [06 Tools](../06_tools/README.md). Инструменты памяти недоступны: у MCP-процесса нет подтверждённой пользовательской сессии. WRITE и EXTERNAL также недоступны. Ограничение: до 60 вызовов в скользящие 60 секунд и до четырёх одновременных исполнений на процесс. Это локальный stdio-сервер, без удалённого HTTP-доступа и фонового запуска.

Проверка из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_mcp_server -v
.\.venv\Scripts\python.exe -m unittest tests.test_mcp_client tests.test_agent_mcp_client -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
git diff --check
```

Интеграционный тест запускает отдельный процесс сервера и обращается к нему реальным MCP-клиентом. Это проверка транспорта без LLM и внешней сети; включённые флагом публичные сервисы тестируются в Phase 6 отдельно. Конкретную конфигурацию вашего MCP-хоста следует сверить с документацией этого хоста.
