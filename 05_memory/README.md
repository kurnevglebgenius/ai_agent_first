# 05 Memory

Оба интерфейса используют `MemoryStore` из `shared/agent_runtime/memory.py`.
База SQLite создаётся автоматически в `05_memory/data/memory.sqlite3` при запуске.
Установка дополнительных пакетов не нужна.

## Что запоминается

- Краткосрочная память: последние 10 завершённых обменов вопрос–ответ. На сообщение сохраняется до 12000 символов; старые обмены удаляются.
- Долговременная память: до 30 явно заданных фактов, каждый имеет название (до 80 символов) и значение (до 1000 символов).
- Структурированное хранение: таблицы `turns` и `facts` в SQLite. Учёт бизнес-операций появится на этапе Business Agent.

История и факты сохраняются между запусками. CLI использует сессию `cli`, Telegram — `telegram:<user_id>`. Их данные разделены. Сохранение вопроса и ответа выполняется одной транзакцией после готового ответа модели. Ошибка модели или превышение лимита инструментов не добавляет незавершённый обмен.

## Команды в Telegram и терминале

```text
/remember имя = Глеб
/remember валюта = BYN
/memory
/forget валюта
/reset
```

`/remember` добавляет факт или заменяет значение с тем же названием. `/memory` показывает факты. Эти команды не обращаются к модели. Модель теперь может сохранять важные факты из обычных сообщений через remember_fact: например, «меня зовут Глеб». Она получает инструкции выбирать устойчивые факты, не сохранять догадки, цитаты, секреты и сообщения с просьбой не запоминать. Это выбор модели, а не гарантированный фильтр. Python проверяет типы, лимиты и дословное присутствие значения и подтверждающей фразы в текущем сообщении. Результат можно проверить через /memory; команды остаются доступны.

`/reset` удаляет локальный диалог, сохраняя факты. `/forget название` удаляет факт и сбрасывает локальный диалог, чтобы старые ответы не возвращали удалённое значение в контекст. История Telegram и данные у LLM-провайдера не удаляются этими командами. Это логическое удаление строк, не гарантированное стирание с диска.

При каждом обычном вопросе факты и последние сообщения передаются модели. Между вопросами используется локальная история вместо цепочки response ID; внутри расчёта цепочка вызовов инструментов сохранена. Факты передаются как пользовательские данные, не системные инструкции. Это не защита от всех возможных манипуляций моделью. База не зашифрована; не сохраняйте в неё пароли и токены. Папка данных исключена из Git.

## Проверка

Перезапустите бот обычной командой из раздела 04, затем:

1. Отправьте `/remember имя = Глеб` и проверьте `/memory`.
2. Задайте обычный вопрос, остановите бот через Ctrl+C и запустите снова.
3. Спросите «Как меня зовут?» — сохранённый факт должен попасть в контекст модели.
4. Выполните `/reset`: `/memory` по-прежнему показывает имя.
5. Выполните `/forget имя`: `/memory` показывает пустую память, локальный диалог сброшен.

Offline-проверки из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются перезапуск хранилища, изоляция сессий, лимиты, удаление, ошибки модели, калькулятор и команды Telegram. Реальные запросы в Telegram и OpenAI в этих тестах не выполняются.

Запись факта выполняется при успешном вызове инструмента. Если следующий запрос к модели или доставка ответа не удались, факт уже может быть сохранён — проверьте /memory. Удаление по-прежнему выполняется через /forget. Новая возможность не извлекает факты задним числом из старых диалогов.
